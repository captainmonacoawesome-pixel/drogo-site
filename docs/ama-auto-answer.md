# Ask Meow Anything on Ripper

Deploy this branch to the Drogo Cloudflare Pages production site first. Its authenticated pending-queue response has a version check to keep older deployments from publishing a historical backlog. The worker uses the existing Access-protected admin API and its atomic pending-only publish operation.

1. In Cloudflare Zero Trust, create a service token named Ripper AMA. On the existing Access application protecting the site's /api/ama/admin path, add a **Service Auth** policy that includes that specific service token. The application must issue a JWT for the audience already configured in ACCESS_AUD. Keep the existing human login policy. The service credential grants moderation access to the protected application, so keep it private. See [Cloudflare service tokens](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/).
2. On Ripper, from the deployed repository checkout, run `sudo bash automation/install-ama-answer.sh`. Select an installed local Ollama chat model from the list, then enter the service token ID and secret at the prompts. Ollama must listen on 127.0.0.1:11434. The installer preserves an existing /etc/drogo-ama-answer.env on rerun. Update that root-only file with sudoedit to change model or rotate credentials.
3. The first successful pass enables a persistent three-hour timer. New pending submissions since first installation are eligible. Earlier submissions remain available in the staff queue. A held submission stays pending for a human. The public question and visitor name are reviewed by the model along with its response decision. Automated review can make mistakes.
4. Submit a fresh question through the normal form, run `sudo systemctl start drogo-ama-answer.service`, then check the public board and `sudo journalctl -u drogo-ama-answer.service -n 15 --no-pager`. A successful publish increments published. Model or network errors leave unanswered items pending for the next pass. A simultaneous staff decision increments raced. Held IDs are stored under /var/lib/drogo-ama-answer.
5. Pause scheduled replies with `sudo systemctl disable --now drogo-ama-answer.timer`. Stop any active pass with `sudo systemctl stop drogo-ama-answer.service`.
